# Spar - Cross-Model Sparring

Adversarial review between the session's tool and its cross-vendor counterpart: the session running this skill is the implementer; the counterpart model is a read-only reviewer in a bridge-controlled headless session. Convergence is evidence-based, and the user arbitrates anything left open.

## Reviewer incantations

Requires: the `claude` CLI, `jq`, and the stowed `spar-claude` bridge (this repo, claude-code/.local/bin), which hard-codes the safe flags: exact first-party claude.ai-subscription preflight with higher-precedence auth, provider, profile, routing, and config environment variables required unset; an explicit read-only tool whitelist (`Read`, `Glob`, `Grep`) backed by plan permission mode and disallowed write tools; safe mode (no plugins, hooks, MCP, or other customizations); the latest permitted Opus family with project/local settings excluded and the user alias override cleared; terminal served-family validation; prompts via stdin; a stall watchdog under an absolute ceiling (SPAR_BRIDGE_STALL and SPAR_BRIDGE_CEILING, positive integers only, defaults 180/1800); and fail-fast usage-limit classification. This repo's workspace-autonomy Bash baseline permits the bridge; the bridge-controlled reviewer can read the handoff without gaining write access.

The reviewer is Claude Code (the bridge-controlled `opus` alias advances with Claude Code's recommended Opus version):

- Handoff: run `spar-claude init`, record its output as `HANDOFF`, and use only that exact path for the run. Recovery discovery: `spar-claude status` lists validated handoffs with task title, mtime, and reviewer manifest.
- First round: run `spar-claude new "$HANDOFF" "<prompt>"` plainly, never via command substitution; the reply text arrives on stderr, the session id on stdout, and the bridge appends timestamped role and state lines (`allocated`, `completed`) to the handoff's `reviewer-id` manifest; state the literal session id in the user presentation.
- Later rounds: `spar-claude resume <id> "$HANDOFF" "<pointer prompt>"`; the reply is stdout. The cold read takes a fresh id from `new` with the trailing role argument `cold`.
- Bridge exit codes: 2 preflight, 3 usage limit, 4 stall, 5 reviewer error, 124 ceiling; all follow the bridge-failure and limit rules.
- Interactive handoff for the user: `claude -r <id>`.

## Modes and Reviews

**Planning:** use the full protocol below. Planning uses blind round 0, full review round 1, and a fresh cold read in round 2. It converges only when round 1 objections are closed, round 2 finds no blocker, and H approves the plan. Plan approval authorizes implementation and the listed reviewer calls, never a commit. Implement each approved atomic unit through the shared workflow and `/commit`; no per-unit reviewer gate is required, and only H's approval of the exact candidate authorizes its commit.

**Review contract:** every mode run has a hard ceiling of round 2 and stops as soon as its mode-specific convergence condition is met. An artifact review that begins at round 1 has only one possible round 2 response; planning reserves round 2 for its cold read. Namespace objections by artifact. A well-formed terminal verdict with zero blockers clears that review regardless of non-blocking count; relay every non-blocking finding and fix it in scope or record it as deferred. A round 1 blocker in brainstorming, final integration, or diff-only permits one evidence-backed amendment or rebuttal in round 2. A planning round 1 blocker must close by plan amendment or H's ruling before the cold read; a rebuttal requiring reviewer acceptance escalates. An unresolved blocker, a missing, truncated, malformed, body-inconsistent, or coverage-incomplete verdict at the ceiling, or an unresolved evidence, value, or scope decision means ESCALATE. Fresh sessions protect blindness; resumed sessions preserve prior review knowledge.

**Final integration review:** mandatory after all planned commits are local and before any push. Use `spar-diff.md` with artifact kind `final integration` and include the approved plan and rulings, starting base, commit list, complete `git diff --binary <base>..HEAD`, clean worktree status, aggregate literal verification, exact warnings and omissions, and a diff hash. Resume the plan-aware primary reviewer when available; otherwise create a fresh primary reviewer. Declare round 1 and require an applicable-class attestation plus cross-unit and plan-drift review. CONVERGED permits reporting readiness only; it never authorizes a commit or push. OPEN returns to H with a proposed fix-forward unit while leaving the worktree intact; no revert, history rewrite, or extra commit is self-authorized, and the final integration review repeats after any fix-forward commit.

**Brainstorming:** use `spar-brainstorm.md` with the user's prompt, outcome, non-goals, constraints, knowns, unknowns, decision horizon, and provisional criteria. Round 0 asks for an independent option set before exposing the implementer's options. Merge both into six fields: option, what it optimizes, cost or risk, reversibility, critical assumption or falsifier, and evidence or cheap test. Round 1 reviews the merged matrix for framing, missing materially distinct options, hidden assumptions, criteria bias, second-order effects, and cheap uncertainty-reducing tests. A brainstorm blocker means the option space is not decision-ready because one of those gaps remains. A clear round 1 converges; otherwise round 2 is the only evidence-backed response. CONVERGED means decision-ready, not option approval. No cold read is required. Present options and disagreements without forcing a recommendation unless requested. If H chooses a direction for execution, complete and clean the brainstorming run, then create a fresh handoff and reviewer session for a genuinely blind planning round 0; expose the prior matrix only in round 1.

**Diff-only:** for work without a sparred plan, use `spar-diff.md` with the goal, charter adapted to implementation review, complete diff, literal verification, and objection log. Create a fresh primary reviewer and declare round 1. Stop on convergence; if blockers remain, round 2 is the only response. The same evidence, closure, verdict, scanner, and user-escalation rules apply.

## Protocol

1. Use the reviewer bridge's `init` mode to create one private `/var/tmp/spar-<session-id>/` directory and state its path; never create or substitute it manually. Draft the mode artifact there, beginning with a target brief: requested outcome, desired end state, non-goals, prior decisions and accepted tradeoffs, constraints, acceptance criteria, and artifact kind. Do not identify the authoring model. Planning adds the approach, ordered steps, files or commands, risks, and open questions. No placeholders; every step names verification. Include an `Evidence Pack` section for each plan-critical changeable external claim: exact claim, primary-source URL, retrieval date, applicable product/version, supporting excerpt or observed output, and dependent step. Local claims cite paths; command claims include the exact command and literal captured output when the reviewer cannot execute it.
2. Keep `spar-objections.md` (id | blocking | claim | status | closure basis): claims are immutable, status and closure basis update in place, rows are never deleted. Pass the exact handoff to every call. After every native file-tool write, run the bridge's `flush` mode before any other action; the bridge also flushes before calls. The bridge's `status` mode supports re-entry, and its `clean` mode owns final cleanup.
3. Planning round 0 sends only the outcome-level brief inline, never the author's plan or mechanisms; ask for a 3-5 bullet independent sketch and material gaps. Round 1 resumes that reviewer with the charter, complete brief, evidence, and plan, asking it to compare against its sketch. Round 2 sends a clean `spar-cold-read.md` containing only the goal, constraints, charter, and final plan to a fresh `cold` session; it receives no objection log or prior transcript and asks only whether any blocker remains. Brainstorming follows its mode sequence.
4. Verify every objection's ground before responding. Amend confirmed issues, rebut disputed ones with evidence, and return ungrounded claims for a ground. Re-fetch disputed external evidence; if unavailable or contradictory, label it unverified and remove its dependent step or escalate. Record dispositions and send the complete amended artifact by pointer.
5. An objection closes only by amendment, refuting evidence the reviewer accepts with a stated reason, or H's ruling. Agreement without evidence or amendment closes nothing. Planning convergence requires all round 1 blockers closed and the round 2 cold read to find no blocker. No mode run continues past round 2; brainstorming, integration, and diff-only stop after any clear review, while planning stops only after its clear cold read.
6. Converged or capped, stop the mode run. Present the final artifact and one self-contained ruling packet per open/disputed item: exact decision requested; facts and uncertainty; both positions, evidence, consequences, and reversibility; affected steps/commits; implementer recommendation labeled judgment; and reviewer ids. Raw reviewer transcripts are never required. For planning, stop before execution; H's go authorizes the plan's edits and verification, not its commits. Other modes authorize no follow-on action by themselves.

## Reviewer charter (send verbatim in round 1)

You are the read-only reviewer in an adversarial artifact loop; a different model drafted the artifact. Challenge logic and evidence, not tone. You review offline: web search, web fetch, and general network access remain disabled. Treat supplied external evidence as traceable but not independently fetched; challenge missing evidence and source-to-artifact reasoning, and never request network access as the remedy. Make each objection one verifiable claim with a concrete failure scenario; number it, label it blocking or non-blocking, and ground it in a file, command, or document. Blocking means: left unaddressed, a plan fails its goal, code or procedure corrupts state or acts irreversibly without recovery, or a brainstorm remains materially incomplete or decision-unready. Round numbers are per mode run and never exceed 2; they reset only for a separately requested mode or the mandatory final integration review, not for amendments or re-prompts. In round 2, raise new objections only if blocking. Treat confidence and verification claims as claims, not evidence. Do not agree to be agreeable: withdraw only for new evidence or amendment, stated explicitly. Before the verdict, sweep and attest every applicable class: code (correctness, contracts, state and migration, failure and rollback, security, test adequacy); procedure (entry conditions, role clarity, branch completeness, handoffs, verification steps, abort path); document (claim-evidence traceability, internal consistency, scope, audience fit, actionability, hostile reader). Mixed artifacts use the union. If nothing blocks on first read, cite the three weakest points. End with `VERDICT: CONVERGED` or `VERDICT: OPEN <blocking> BLOCKING / <non-blocking> NON-BLOCKING`.

## Rules

- The reviewer is advisory and read-only; the implementer alone edits files, and the bridge appends only the reviewer-id manifest. Workspace edits happen only after H approves the plan; handoff drafting precedes approval by design.
- The implementer owns current external verification and supplies the evidence pack.
- Relay reviewer objections in substance; do not soften or reframe them. Reviewer-labeled non-blocking unverifiable evidence permits GO with relay; ESCALATE requires a blocking evidence dispute, value judgment, scope drift, or ceiling.
- Disagreements the implementer cannot resolve with evidence go to the user as disputed items, never silently accepted or dropped.
- If the reviewer bridge fails, report and stop; never substitute self-review.
- A reviewer usage-limit error surfaces to the user immediately, with any reset information; never retry into a limit.
- The final report gives the call count for each mode run and records any usage-limit, stall, or ceiling event.
- Handoff files are written with the native file tools only; shell write channels into the handoff stay gated.
- If scanning rejects a known-safe prose draft, correct it in place with native tools; if it rejects a complete diff/verification artifact, never alter or exempt that artifact merely to pass, stop for H. If no safe representation exists, stop for H.
- Re-entry after interruption: run the bridge's `status` mode, select the handoff by task title, and resume the newest `primary` manifest entry with state `completed`; if only earlier states exist, try that id and fall back to a fresh thread seeded from the handoff files; an unrecorded thread likewise gets a fresh thread, repeating at most one call. `cold` entries are cold reads. If no valid handoff survives, run fresh `init` and re-draft.
- Use the reviewer bridge's `clean` mode to delete this session's validated `/var/tmp/spar-<session-id>/` directory during completion cleanup.
