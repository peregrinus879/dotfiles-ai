## Known Limitations

- OpenCode upstream shows a multi-file `apply_patch` as one approval dialog; the local `reviewed-writes.ts` plugin rejects grouped patches before permission, while the shared and OpenCode-local one-file instructions guide all managed tools (anomalyco/opencode#21914 closed not planned; linked PR #23262 remained open on 2026-08-14)
- rule order in the OpenCode `bash` permission map is semantic (rules are last-match-wins over per-command text including redirects): catch-all ask first, allows, then the redirect ask guards, denies last; `make verify` asserts no allow entry after the guard block
- the Claude Code redirect ask guards (`Bash(* >*)`, `Bash(* | tee*)`) mirror the OpenCode ask guards and stay ask-gated, never allowed; they match any command containing ` >` or `| tee`, including inside quoted arguments, so harmless matches prompt instead of hard-failing; live-verified 2026-08-08 on 2.1.226: they re-gate allowed commands in default mode, but in auto mode operator-based guards never match at all (redirects and pipe segments are invisible to ask matching; reported as anthropics/claude-code#85098) while text-matching guards like `Bash(*sed*-i*)` still prompt; shell write channels in auto mode therefore rest on the soft_deny prose alone, and `autoMode.classifyAllShell` stays pinned `true` so allowlisted commands reach the classifier instead of executing unexamined
- Claude Code, Codex, and OpenCode may invoke the managed commit and spar skills when relevant; explicit commit authorization and phased-work approval still govern tracked commits and spar execution.
- skill `allowed-tools` frontmatter is Claude Code-only and pre-approves listed tools for the invoking turn rather than restricting them; the OpenCode commit skill keeps per-command prompts, and `make verify` allows that frontmatter diff between the copies
- `workflowSizeGuideline` is pinned `large`, the highest bounded advisory level: it does not cap execution or change model effort and preserves more breadth than the app's `medium` default
- do not add allow rules for Claude Code's built-in auto-run read-only Bash commands; they are redundant, and a blanket allow like `Bash(file *)` overrides the built-in re-prompt on write-capable flag forms (`file -m`)
- Claude Code writes app-managed state into `settings.json` through the stow symlink (its own key order plus internal keys like `skipWorkflowUsageWarning`); commit those rewrites as-is instead of reverting them
- the in-place-editor ask guards (`Bash(*sed*-i*)`, `Bash(*perl *)`, `Bash(*| perl*)`, `Bash(*awk*inplace*)`, mirrored as ask entries in the OpenCode guard block) share the redirect guards' substring matching and fresh-session verification note; combined short flags (`sed -ri`, `sed -Ei`, `sed -ni`, `ruby -i`) escape the globs and rely on the auto-mode soft_deny prose plus the shared-guidance ban on shell bulk edits
- auto-mode edit gating is layered deliberately: the spar gate hook's per-file ask fallback and text-matching shell guards are the deterministic first line, while operator-based redirect and pipe guards do not match in auto mode; the two filesystem soft_deny prose lines are the probabilistic backstop. Bare `Edit`/`Write`/`NotebookEdit` ask entries stay out of the list: live probes on 2.1.233 (2026-08-17, with a non-handoff control) showed a matching ask rule overrides a PreToolUse hook allow while the hook allow works when no ask rule matches, and current docs plus anthropics/claude-code#35136 record rule-over-hook precedence (deny rules also override hooks). The gate hook blocks (exit 2) when it cannot decide; the residual is a manually half-broken stow (hook file gone, settings intact), which falls through to auto-mode defaults until `make verify` and the contracts pins catch it. Plain `rm`, formatters, and writes hidden inside script files (`python gen.py`) are left to the classifier prose as a recorded scope decision, and session scratch deletion under `/tmp/claude-*` is a recorded `autoMode.allow` exception to the deletion line (repeated classifier blocks would pause auto mode during mandated cleanup)
- OpenCode `--auto` auto-approves every `ask` entry including `permission.edit` (only `deny` rules hold), so per-file edit review exists only in default OpenCode sessions; the mirrored guards harden default sessions only
- OpenCode out-of-project credential-shaped coverage is two-layered on both channels, 2026-08-17: layer 1, the `external_directory` catch-all ask gates any out-of-project read or edit (probe-verified on `/var/tmp/probe-cred.key` for both channels; headless auto-reject); layer 2, the relative `**/*.key`-class read and edit denies match worktree-relative subjects, so they still block a credential-shaped file even after an interactive external approval (semantics-verified via the evaluated-rule dump and the in-handoff canary probe; the leading `../` segments are absorbed by the anchored `*`). Claude Code reaches the same outcome with absolute `//**/*` deny globs; parity is by different mechanisms
- the OpenCode bash allowlist carries the same read-only wildcard forms as the Claude allowlist (`tree *`, `pacman -Q*`, `pacman -Si *`, `pacman -Ss *`) by decision 2026-08-17, so those commands run prompt-free in both tools; the `tree -o`/`--output` denies sit last and keep winning under last-match-wins; 2026-08-17 fresh-session probe: `tree -L 1` and `pacman -Si stow` ran prompt-free, `tree -o` was denied
- OpenCode WebFetch is allowed without prompts to match ordinary Claude auto-mode research, but OpenCode 1.18.18 has no equivalent classifier, hostname canonicalization, resolved-address check, or redirect-aware SSRF boundary; sensitive reads and shell network remain separately gated, and fetched or queried content must never carry repository-sensitive data
