# Spar - Cross-Model Sparring

Adversarial review between the session's tool and its cross-vendor counterpart: the session running this skill is the implementer; the counterpart model is a read-only reviewer in a bridge-controlled headless session. Convergence is evidence-based, and the user arbitrates anything left open.

## Reviewer incantations

Requires: the `codex` CLI and the stowed `spar-codex` bridge (this repo, codex/.local/bin), which hard-codes the safe flags: exact ChatGPT-subscription and effective-plugin-disable preflights with `CODEX_API_KEY` required unset; ignored user config and rules; strict config; an inline read-only reviewer profile with sensitive-path denies, handoff reads, network disabled, and a secret-filtered shell environment; max effort with reasoning summaries disabled; MCP, apps, local and remote plugins, hooks, web search, multi-agent, skill-install, and shell-snapshot surfaces disabled; stdin guard; a 180 s stall watchdog under a 1800 s ceiling; fail-fast usage-limit classification; bounded payload-scanned stderr diagnostics; failed-new thread reporting; never `--last`. Tracked permissions auto-approve `Bash(spar-codex *)`; the pinned reviewer can read the handoff without gaining write access.

The reviewer is Codex (model pinned inside the bridge; update it there when the preferred model changes):

- Handoff: run `spar-codex init`, record its output as `HANDOFF`, and use only that exact path for the run. Recovery discovery: `spar-codex status` lists validated handoffs with task title, mtime, and reviewer manifest.
- First round: run `spar-codex new "$HANDOFF" "<prompt>"` plainly, never via command substitution (allow rules do not match `$(...)` forms); the reply text arrives on stderr, the thread id on stdout, and the bridge appends timestamped role and state lines (`started`, `completed`) to the handoff's `reviewer-id` manifest; state the literal thread id in the user presentation. If the fresh thread starts but the call later fails, the manifest and the `SPAR-BRIDGE THREAD` stderr line preserve the id.
- Later rounds: `spar-codex resume <id> "$HANDOFF" "<pointer prompt>"`; the reply is stdout. The cold read takes a fresh id from `new` with the trailing role argument `cold`.
- Bridge exit codes: 2 preflight, 3 usage limit, 4 stall, 5 reviewer error, 124 ceiling; all follow the bridge-failure and limit rules.
- Interactive handoff for the user: `codex resume <id>`.

## Modes and Gates

**Planning and execution:** use the full protocol below. The plan gate requires zero open blocking objections, a fresh cold read with no new blocker, and H's approval. Plan approval authorizes implementation and the listed reviewer calls, never a commit. Each approved atomic implementation unit then receives an implementation gate after the `/commit` workflow's documentation, scratch, and identity preparation plus local verification, but before H's exact-diff review, staging, and commit phases. The final integration gate reviews the complete starting-base-to-HEAD change after all units are committed locally and before any push. Reviewer GO permits presentation of the candidate to H; only H's approval of that exact candidate authorizes its commit. An atomic unit is one independently coherent, testable change whose dependencies, documentation, and enforcement land together. Gates attach to approved units, never individual edits, commands, or tests.

**Gate contract:** resume the plan-aware primary reviewer, but declare artifact round 1 and restate the verdict grammar, both severities, and every applicable coverage class. Mixed artifacts use the union of code, procedure, and document classes. Namespace objections by artifact (`P-*`, `I1-*`, `G-*`). A well-formed terminal verdict with zero blockers means GO regardless of non-blocking count; relay every non-blocking finding and fix it in-unit or record it as deferred. A blocking finding prevents GO but permits evidence-backed remediation of the current unit and a response within budget; unresolved blockers at the boundary mean NO-GO. Missing, truncated, malformed, body-inconsistent, or coverage-incomplete verdicts never mean GO. Each implementation or integration gate permits at most three calls total across challenge, response, one targeted verdict re-prompt, and one content-change re-entry, with nine calls across execution gates overall; an H-approved plan's lower execution budget controls, and either exhaustion means ESCALATE. Fresh sessions protect blindness; resumed sessions preserve approved-plan knowledge.

**Implementation packet:** include the approved unit, complete diff and literal verification output, exact known warning text, worktree status, disclosed omissions, intended untracked file contents without mutating the index, and a hash of `git diff --binary HEAD`. Scan the complete packet, never edit or exempt a diff merely to pass scanning, require live-file spot checks and bidirectional plan drift review, then verify the hash again immediately before H's review. Any content edit after GO re-enters once; a second edit escalates. At NO-GO or ESCALATE, leave the worktree intact, disclose status and verification, and never begin the next unit, stash, revert, or discard without H's instruction.

**Final integration gate:** send the starting-base-to-HEAD diff, worktree status, aggregate verification, and approved plan; require an artifact-round-1 attestation and cross-unit drift review. Nothing pushes before GO. Integration NO-GO returns to H with a proposed fix-forward unit; no revert, history rewrite, or extra commit is self-authorized.

**Brainstorming:** use `spar-brainstorm.md` with the user's prompt, outcome, non-goals, constraints, knowns, unknowns, decision horizon, and provisional criteria. Round 0 asks for an independent option set before exposing the implementer's options. Merge both into six fields: option, what it optimizes, cost or risk, reversibility, critical assumption or falsifier, and evidence or cheap test. Challenge framing, missing materially distinct options, hidden assumptions, criteria bias, second-order effects, and cheap uncertainty-reducing tests. A brainstorm blocker means the option space is not decision-ready because one of those gaps remains. A well-formed CONVERGED verdict maps to brainstorm GO: decision-ready, not option approval; an open blocker means NO-GO and permits one evidence-backed response; an unresolved value judgment, evidence or scope decision, or response ceiling means ESCALATE. No cold read is required. Present options and disagreements without forcing a recommendation unless requested. If H chooses a direction for execution, complete and clean the brainstorming run after capturing H's outcome-level decision, then create a fresh handoff and reviewer session for a genuinely blind planning round 0; expose the prior matrix only in round 1.

**Diff-only:** for work without a sparred plan, use `spar-diff.md` with the goal, charter adapted to implementation review, complete diff, literal verification, and objection log. Create a fresh primary reviewer, declare artifact round 1, and run one review under the gate contract; the same evidence, closure, verdict, scanner, and user-escalation rules apply.

## Protocol

1. Use the reviewer bridge's `init` mode to create one private `/var/tmp/spar-<session-id>/` directory and state its path; never create or substitute it manually. Draft the mode artifact there, beginning with a target brief: requested outcome, desired end state, non-goals, prior decisions and accepted tradeoffs, constraints, acceptance criteria, and artifact kind. Do not identify the authoring model. Planning adds the approach, ordered steps, files or commands, risks, and open questions. No placeholders; every step names verification. Include an `Evidence Pack` section for each plan-critical changeable external claim: exact claim, primary-source URL, retrieval date, applicable product/version, supporting excerpt or observed output, and dependent step. Local claims cite paths; command claims include the exact command and literal captured output when the reviewer cannot execute it.
2. Keep `spar-objections.md` (id | blocking | claim | status | closure basis): claims are immutable, status and closure basis update in place, rows are never deleted. Pass the exact handoff to every call. After every native file-tool write, run the bridge's `flush` mode before any other action; the bridge also flushes before calls. The bridge's `status` mode supports re-entry, and its `clean` mode owns final cleanup.
3. Planning round 0 sends only the outcome-level brief inline, never the author's plan or mechanisms; ask for a 3-5 bullet independent sketch and material gaps. Round 1 sends the charter, complete brief, evidence, and plan, asking the reviewer to compare against its sketch. Brainstorming follows its mode sequence.
4. Verify every objection's ground before responding. Amend confirmed issues, rebut disputed ones with evidence, and return ungrounded claims for a ground. Re-fetch disputed external evidence; if unavailable or contradictory, label it unverified and remove its dependent step or escalate. Record dispositions and send the complete amended artifact by pointer.
5. An objection closes only by amendment, refuting evidence the reviewer accepts with a stated reason, or H's ruling. Agreement without evidence or amendment closes nothing. Planning convergence requires zero blockers and a clean `spar-cold-read.md` containing only goal, constraints, charter, and final plan; a fresh `cold` session must find no blocker. Planning has a four-round ceiling, not a target.
6. Converged or capped, stop before execution. Present the final artifact and one self-contained ruling packet per open/disputed item: exact decision requested; facts and uncertainty; both positions, evidence, consequences, and reversibility; affected steps/commits; implementer recommendation labeled judgment; and reviewer ids. Raw reviewer transcripts are never required. H's go authorizes the plan's edits and verification, not its commits.

## Reviewer charter (send verbatim in round 1)

You are the read-only reviewer in an adversarial artifact loop; a different model drafted the artifact. Challenge logic and evidence, not tone. You review offline: web search, web fetch, and general network access remain disabled. Treat supplied external evidence as traceable but not independently fetched; challenge missing evidence and source-to-artifact reasoning, and never request network access as the remedy. Make each objection one verifiable claim with a concrete failure scenario; number it, label it blocking or non-blocking, and ground it in a file, command, or document. Blocking means: left unaddressed, a plan fails its goal, code or procedure corrupts state or acts irreversibly without recovery, or a brainstorm remains materially incomplete or decision-unready. Round numbers are per artifact review and reset only when the gate prompt explicitly declares artifact round 1; within an artifact, from round 2 on raise new objections only if blocking. Treat confidence and verification claims as claims, not evidence. Do not agree to be agreeable: withdraw only for new evidence or amendment, stated explicitly. Before the verdict, sweep and attest every applicable class: code (correctness, contracts, state and migration, failure and rollback, security, test adequacy); procedure (entry conditions, role clarity, branch completeness, handoffs, verification steps, abort path); document (claim-evidence traceability, internal consistency, scope, audience fit, actionability, hostile reader). Mixed artifacts use the union. If nothing blocks on first read, cite the three weakest points. End with `VERDICT: CONVERGED` or `VERDICT: OPEN <blocking> BLOCKING / <non-blocking> NON-BLOCKING`.

## Rules

- The reviewer is advisory and read-only; the implementer alone edits files, and the bridge appends only the reviewer-id manifest. Workspace edits happen only after H approves the plan; handoff drafting precedes approval by design.
- The implementer owns current external verification and supplies the evidence pack.
- Relay reviewer objections in substance; do not soften or reframe them. Reviewer-labeled non-blocking unverifiable evidence permits GO with relay; ESCALATE requires a blocking evidence dispute, value judgment, scope drift, or ceiling.
- Disagreements the implementer cannot resolve with evidence go to the user as disputed items, never silently accepted or dropped.
- If the reviewer bridge fails, report and stop; never substitute self-review.
- A reviewer usage-limit error surfaces to the user immediately, with any reset information; never retry into a limit.
- The final report gives the call count for each gate and records any usage-limit, stall, or ceiling event.
- Handoff files are written with the native file tools only; shell write channels into the handoff stay gated.
- If scanning rejects a known-safe prose draft, correct it in place with native tools; if it rejects a complete diff/verification artifact, never alter or exempt that artifact merely to pass, stop for H. If no safe representation exists, stop for H.
- Re-entry after interruption: run the bridge's `status` mode, select the handoff by task title, and resume the newest `primary` manifest entry with state `completed`; if only earlier states exist, try that id and fall back to a fresh thread seeded from the handoff files; an unrecorded thread likewise gets a fresh thread, repeating at most one call. `cold` entries are cold reads. If no valid handoff survives, run fresh `init` and re-draft.
- Use the reviewer bridge's `clean` mode to delete this session's validated `/var/tmp/spar-<session-id>/` directory during completion cleanup.
