# AGENTS.md - EyrAgents

This repo stores portable user-level AI assistant configuration for Claude Code, Codex, and OpenCode: the stowed `claude-code/`, `codex/`, and `opencode/` payloads, the directly stowed spar reviewer bridges, the shared cross-tool guidance file, and the commit workflow used by all managed tools. Auth, session state, machine-local files, and generated host-specific config stay out except for the documented app-managed rewrites inside tracked runtime config.

## Load Map

- Claude Code loads `~/.claude/CLAUDE.md` and `~/.claude/rules/*.md` (stowed from `claude-code/`), then this file through the root `CLAUDE.md` `@AGENTS.md` import.
- Codex loads `~/.codex/AGENTS.md` (stowed from `codex/`, a symlink chain to the shared guidance file), then this file natively as the repo-root `AGENTS.md`.
- OpenCode loads the shared guidance file through `instructions` in `opencode.json`, then this file.
- Skills load on invocation only. Repo-root docs are not stowed; `docs/maintenance.md` is an on-demand ledger, not session instructions.
- Repo-root `.claude/settings.json` and `opencode.json` are inert per-tool project config placeholders with no command grants.

## Invariants

- Shared cross-tool guidance is canonical in `claude-code/.claude/rules/shared-guidance.md`; extend it for new shared guidance and keep tool-specific mechanism in each tool's wrapper (share policy, separate mechanism). Codex consumes it through the `codex/.codex/AGENTS.md` symlink chain, never a copy.
- Sequence rule: every repo list, tree, and doc orders the tools Claude Code, Codex, OpenCode.
- Reviewer matrix (cross-vendor, subscription auth only): Claude Code spars with Codex via `spar-codex`; Codex's automated Claude path remains deferred under its strict profile; OpenCode spars with Claude via `spar-claude`. The directly stowed bridges hard-code their safety flags, reject higher-precedence non-subscription authentication, caller-directed state or routing, Git-control variables, repository hard-linked files outside denied directories, and nested repository mounts; use startup-isolated interpreters; resolve one reviewer executable before changing directories; preflight subscription auth fail-closed; validate their timeout knobs (zero or malformed values abort); and own the private handoff lifecycle. Both reviewers launch from the caller's canonical Git root, receive one scanner-produced finite prompt on stdin, and may read that repository plus the exact handoff except for Git internals, credential-shaped paths, and `reviewer-id`; repository files outside those denies may reach the subscription reviewer, including private-repository files. `spar-codex` ignores user config and rules, suppresses project instructions and skill catalogs, disables plugin loading, fails closed unless the same override leaves a structurally valid empty plugin inventory, rejects repository entries beyond its bounded deny-glob depth, and uses one strict inline profile with root and temp denied, runtime-minimal paths plus the repository and handoff readable, later sensitive-path denies, and command network disabled. It retains the normal `CODEX_HOME` for ChatGPT authentication and resumable session state. `spar-claude` adds the handoff to the repository launch, exposes only `Read`, `Glob`, and `Grep`, applies explicit allow and later deny rules, uses safe mode with no user, project, or local setting sources, discovered `CLAUDE.md`, auto memory, or extension tools, clears the Opus-alias override, and validates the terminal served-model family. Higher-precedence managed Claude policy remains in force.
- Reviewer preflight and repository binding reject filesystem-root repositories and run Claude authentication under the review's safe-mode setting-source isolation; ambient third-party provider, endpoint, and auth-skip controls fail closed. Claude's inline policy retains absolute account-home credential denies even when a repository grant overlaps them.
- Reviewer repository path preflight validates every canonical-root component's spelling and every repository entry name it enumerates without reading file contents. It prunes the repository-root `.git` and exact repository-root `secrets` subtrees and does not follow directory symlinks. Before authentication it rejects nested `.git` directories, sensitive directories without exact subtree denies, sensitive-named symlinks, symlinks below nested `secrets` trees whose deny depends on glob expansion, case variants of sensitive names, non-UTF-8 names, and control-, quote-, or backslash-bearing names. Ordinary public symlinks remain reviewable. Hard-link scans prune only the root Git metadata subtree and exact lowercase `secrets` directories. The outbound scanner parses LF-delimited Git records and strictly decodes C-quoted paths before applying the shared sensitive-name grammar to every path component; reviewer policies and native handoff-write gates cover that grammar's dotenv, secret, auth, credential-dotfile, credential-extension, and OpenSSH key forms.
- Spar reviewers remain offline and read-only. Plan and build are the primary spar checkpoints, not mandatory gates; the implementer may spar at any other point and chooses review timing, context, topology, and depth from expected value. Every substantive review receives the target, a Decision Rationale covering the evidence, alternatives, tradeoffs, H's rulings, and authorized changes, plus traceable support for current external claims. Reviewers focus challenges to supported decisions on concrete defects or consequences rather than relitigating them merely because another approach exists; every user escalation is a self-contained ruling packet with both positions, consequences, and an implementer recommendation.
- When editing sibling dotfiles repos, use identical wording for shared concepts; only repo-specific values (scope, package lists, invariants) differ.
- Keep wrappers thin; detailed rationale goes in `README.md`.
- Versioned probes, limitations, deferred work, and watch items live in `docs/maintenance.md`. Probe versions are historical evidence, not installed-version pins or routine synchronization targets. Read the ledger before a tool or plugin major-version upgrade, permission or bridge changes, cross-host validation, `/doctor`, or deferred work; re-fetch affected facts when a relevant interface, behavior, major version, or configuration changes.
- Commit boundaries never alter, stage, or temporarily revert unrelated hunks. A mixed file is deferred or escalated to H for a split decision.
- Execute one approved commit unit at a time: edit and verify autonomously, present its exact candidate for H's editor review, commit only that approved candidate, then follow H's selected continue or discuss route without inferring another commit or publication authorization.
- A clear task request authorizes value-based read-only spar calls within its scope; invoking a skill alone authorizes nothing outside an active request. A plan approval authorizes its listed edits, verification, reviewer calls, and deployment steps, never a commit. Every commit requires H's approval of the exact content, intended paths, message, audience, and scratch disposition; any later change invalidates that approval.
- The managed `/commit` workflow screens each candidate for audience-inappropriate context and withholds publication-ready claims and push hints until a destination-bound review reconciles every commit and artifact version the action would newly expose to its audience. Shared guidance owns the policy; the commit skills own the procedure, and code review or secret scanning never substitutes for the privacy review.
- Claude Code pins `permissions.defaultMode` `"auto"` and disables bypass mode. Its spar hook allows validated handoff writes, denies unsafe spar-shaped targets, and defers ordinary edits to auto mode; sensitive-path denies override hook decisions. Codex uses a write-capable trusted-workspace profile with OS-enforced sensitive-path and network restrictions plus automatic approval review. OpenCode permits ordinary workspace edits and shell commands by default, denies sensitive paths, external-directory access, and common destructive, privileged, upload, and remote-mutation commands, and retains a documented residual for mutations hidden inside wrappers or scripts because it has no classifier or OS sandbox. The Claude `autoMode` guardrails keep `"$defaults"` first so built-in rules survive.
- Primary web research follows Claude auto mode's outcome: unmatched Claude WebSearch and WebFetch calls reach the classifier; Codex uses hosted live search while shell network stays disabled; OpenCode allows WebSearch and WebFetch without prompts, but has no equivalent classifier or SSRF boundary. Reviewers remain search-disabled.
- Do not add Claude Code allow rules for built-in auto-run read-only Bash commands; blanket rules can suppress built-in re-prompts on write-capable flag forms.
- Claude Code requests Fable 5 with maximum effort through `CLAUDE_CODE_EFFORT_LEVEL=max`, the supported persistent path because `effortLevel` does not accept `max`. `spar-claude` instead selects Claude Code's latest permitted Opus family with `--effort max`, validates the served family, and disables nonessential traffic and updater activity; organization-managed model or effort limits remain higher precedence.
- Claude Code pins `workflowSizeGuideline: large`, the highest bounded advisory level; dynamic workflows remain enabled, while maximum effort deliberately keeps ultracode orchestration inactive.
- Claude Code writes app-managed state and key ordering into tracked `settings.json`; Codex and the ChatGPT desktop app write project trust, notices, marketplace and plugin state, MCP/runtime entries, and desktop preferences into tracked `config.toml`. Commit those rewrites as-is instead of reverting them, and revalidate generated runtime paths on each host.
- Codex uses the beta `trusted-workspace` permission profile: workspace and OS temporary roots writable, Git metadata protected by the inherited `:workspace` boundary, sensitive paths denied, command network disabled, and `approvals_reviewer = "auto_review"`. `spar-codex` ignores user config and independently supplies a profile with root and temp denied, runtime-minimal paths plus the canonical repository and handoff readable, later Git, credential-path, and manifest denies, and command network disabled.
- Every scripted `codex exec` uses either `</dev/null` for a no-payload command or one scanner-produced finite bundle as prompt stdin, never uses concurrency-unsafe `--last`, and selects the same strict reviewer profile for new and resumed calls. Codex skills live under `~/.agents/skills`, never the app-managed `~/.codex/skills` tree.
- Codex, OpenCode, and `spar-codex` pin GPT-5.6 Sol Fast. Codex uses the base `gpt-5.6-sol` slug with Ultra reasoning and automatic summaries for the primary, while spawned subagents inherit Fast and default to Max. OpenCode uses its catalog's `openai/gpt-5.6-sol-fast` alias with tracked base options for Max reasoning and automatic summaries; an explicitly selected TUI variant persists and takes precedence over those base options. Primary agents use the global default and subagents inherit it from the invoking primary. `spar-codex` pins Max, disables summaries and multi-agent delegation, and retains its single-reviewer isolation. The managed configuration assumes ChatGPT subscription auth; a ChatGPT Pro plan raises included limits but does not enable Responses API Pro reasoning mode, while API-key use is separately billed and requires a separate configuration decision.
- Read `README.md` before structural changes; when the installed OpenCode binary and its docs disagree, prefer `/help` output and runtime behavior.
- Auth, session state, machine-local files, and generated host-specific files stay out of Git; the app-managed rewrite exception above applies only inside the tracked Claude `settings.json` and Codex `config.toml`. Keep the tracked nested payload ignore files aligned with the documented exclusions.
- Spar handoffs use one private mode-700 `/var/tmp/spar-<session-id>/` directory per session on disk-backed OS temp, so an in-flight review survives reboots. The selected bridge owns the lifecycle: create, revalidate before every call and before cleanup, flush before every call (the same durability step is its `flush` mode, run after every native handoff write), scan through descriptor-relative no-follow reads, and clean. The reserved six-field `reviewer-id` manifest namespaces the bridge and reviewer role, binds every new or resumed session to the canonical repository root, rejects prior manifest shapes, and never permits a cold session to resume. Reviewers receive the handoff as a read-only context root but cannot read the manifest. Handoff writes through the native file tools are prompt-free in the implementer tools; the Claude gate hook and `reviewed-writes.ts` canonicalize inward symlink aliases before applying reserved-name and alias-safe metadata checks. Shell write channels into the handoff stay gated (rule shapes, validation properties, and probes: `docs/maintenance.md`).
- Every spar call passes its prompt and complete handoff through the directly stowed isolated `spar-payload-scan` before authentication or reviewer network access. Outbound scanning rejects sensitive handoff filenames, common credential shapes, reviewer-instruction files, and sensitive Git diff paths; bounds prompt size, entry count, individual files, aggregate bytes, and reported finding count; and refuses binary, non-UTF-8, linked, malformed, or oversized artifacts. Public synthetic exceptions bind detector schema, rule ID, and exact matched-span digest internally, so changed spans remain blocked; rejection diagnostics expose no span or span-derived digest. The separate reply and diagnostic channel rejects secret values while permitting discussion of sensitive path names. Unrecognized secret formats remain a residual prose-gate risk.
- Both reviewer bridges require ordered session events, bind successful results to the requested session or thread, require one valid terminal success event and a nonempty locally rescanned reply, and own the reviewer process group. `spar-codex` captures bounded reviewer stderr in its private work directory, relays it only after reply-channel scanning, classifies stderr-only limits, and reports a valid new thread ID if that thread later fails. `spar-claude` reports an allocated new-session ID on later failure. Signal, repeated-signal, stall, ceiling, and normal leader exits terminate remaining descendants before the bridge returns.
- Global permissions are the trusted-repository default, not a boundary against project settings or plugins. Use the README's project-disabled launch commands for untrusted checkouts; verification proves those launches retain the global OpenCode write-review plugin.
- OpenCode's host environment disables automatic Claude/Codex skill discovery so the managed OpenCode commit and spar copies win deterministically; `skills.paths` explicitly retains only the Omarchy skill. Non-interactive launchers and untrusted-checkout commands supply the same external-skill isolation variable themselves.
- Claude Code skill `allowed-tools` frontmatter pre-approves named tools for the invoking turn rather than restricting the skill; OpenCode keeps command prompts, and verification permits that tool-specific difference.
- OpenCode applies one file per `apply_patch`: shared guidance sets the policy and `reviewed-writes.ts` rejects grouped or malformed patches before permission.
- OpenCode `bash` permission order is semantic and last-match-wins: the catch-all workspace-autonomy allow comes first and hard denials follow it. Direct command denials and the finite upstream external-path scanner are defense in depth, not a shell sandbox; unrecognized direct readers, dynamic path arguments, wrappers, and scripts remain governed by shared instructions and final diff review.
- OpenCode plugin dependencies use a compatible-major manifest range and a reproducible lockfile independently of the installed OpenCode release; only generated `node_modules/` stays ignored. Re-evaluate the range when the plugin API crosses a major compatibility boundary, not for routine client releases.
- OpenCode in-app updates stay disabled because the external installation wrapper owns version selection; the tracked provider block contains only providers used by a managed model.
- Stow tree-folds directories that do not pre-exist at stow time into directory symlinks pointing at the repo. `make clean` keeps runtime-state parents (`~/.claude`, `~/.claude/skills`, `~/.codex`, `~/.agents`, `~/.agents/skills`, `~/.local`, `~/.local/bin`, and `~/.config`) real before stowing; absent `~/.config/opencode` may fold wholesale, while an existing real root receives managed child links (do not add `--no-folding`). The three reviewer executables deploy through the same direct Stow links as the other managed payloads.
- `make verify` resolves every tracked or untracked, non-ignored package file, including the three reviewer executables, to its deployed target. The three package-internal `.gitignore` files remain source-only because GNU Stow ignores them by default.
- Never weaken the sensitive-path deny rules: keep `~/.ssh` denied in Claude Code's Read rules, Codex's filesystem profile, and OpenCode's read and external-directory permissions; keep `Bash(gh api *)` in Claude Code and `gh api *` in OpenCode denied (H runs those via `!`). OpenCode's external-directory guard covers only Bash commands recognized by its upstream path scanner; its shell residual is recorded in `docs/maintenance.md`.
- The Claude automatic shell allowlist is deliberately narrow; do not restore `Bash(gh search *)`, `Bash(jq *)`, or `Bash(opencode debug *)` without a new decision from H.
- Sensitive-path Edit denies mirror unambiguous credential material only; deterministic read denies make agent editing of existing sensitive files impractical in both namespaces. OpenCode denies all external-directory access except validated spar handoffs. Explicit sensitive or external exceptions run through H's `!` terminal, not the agent. Use `example.env` for editable placeholder templates.
- `statusline.sh` design conventions, including its intentional strict-mode omission, live in the script's header comment.
- `statusline.sh` persists hashed state names under one owner-validated mode-700 runtime directory and accepts only owner-only, mode-600, regular, single-link state files. Unsafe root metadata disables all persistence; an unsafe state file disables only that entry, and neither is followed, repaired, or replaced.
- `/doctor` may delete machine-local accumulated allowlists and rewrite app-managed state; review its findings first, then curate durable safety rules instead of restoring local allowlists wholesale.

## Post-Change Verification

- Run `make verify` and `make lint` from the repo root after changing the stowed payloads.
- After instruction or config changes, verify them in fresh Claude Code, Codex, and OpenCode sessions when practical.
- The full human checklist lives in `README.md` (Verify and Maintenance).
